# 04 产品需求文档

## 1. 背景与目标

WebLearnBoost 的目标不是再做一个普通网页摘要器，而是把 AI 技术网页资料转换成可学习、可复习、可验证的学习包。

前面的 `01_问题定义.md`、`02_用户调研.md`、`03_竞品分析.md` 已经说明：用户在学习 RAG、Agent、MCP、AI 框架等内容时，最在意的不是“看完了吗”，而是：

- 有没有先帮我建立学习路径
- 有没有抓住核心重点
- 有没有把概念关系讲清楚
- 有没有让我确认自己真的学会了
- 能不能随时回到原文核对

因此，第一版 PRD 的目标很明确：

> 让用户在打开一篇 AI 技术网页后，能够先看到学习地图，再进入训练过程，最后通过重点摘要、选择题自测和原文依据完成一次轻量但完整的学习闭环。

## 2. 用户与使用场景

### 2.1 目标用户

第一版目标用户是正在自学 AI 技术内容的人，尤其是会主动阅读以下资料的人：

- RAG、Agent、MCP、tool calling、workflow 等 AI 应用开发概念
- LangChain、LlamaIndex、Dify、FastAPI + LLM 等框架或工程实践
- 向量数据库、检索增强、提示词工程、模型调用等相关知识

这类用户通常不是完全的小白，而是已经开始进入技术学习阶段，但面对网页资料时，容易出现“当下看懂、过后讲不清、也不知道是否漏掉重点”的问题。

### 2.2 典型场景

1. 用户打开一篇 AI 技术教程或官方文档。
2. 用户希望先知道这篇资料该怎么学，而不是直接被一大段内容淹没。
3. 用户阅读或浏览后，希望快速抓住重点、形成可复习材料。
4. 用户希望通过自测确认自己是否真正理解。
5. 用户希望能回到原文核对关键结论，并把结果保存下来。

### 2.3 用户故事

- 作为一个 AI 技术自学者，我希望打开网页后先看到学习地图，这样我知道这篇资料该怎么学。
- 作为一个 AI 技术自学者，我希望生成重点摘要和选择题自测，这样我能判断自己是不是真的学会了。
- 作为一个 AI 技术自学者，我希望每条重要内容都能回到原文，这样我能确认 AI 没有漏讲或乱讲。

## 3. MVP 范围与非目标

### 3.1 第一版必须做

| 能力 | 说明 |
|---|---|
| 学习地图 | 用户打开网页后，第一屏先看到学习路径、核心结构和推荐阅读顺序。 |
| 重点摘要 | 将当前网页转成重点内容，中文解释并保留英文术语。 |
| 选择题自测 | 围绕核心内容生成题目，并支持逐题反馈答案、解析和原文依据。 |
| 原文摘录 + 简单定位 | 每条重点和题目解析尽量带原文摘录，并尽量回到网页中的位置。 |
| 本地保存 | 学习包保存在浏览器本地，可回看和删除。 |
| Markdown 导出 | 支持把整个学习包导出为 Markdown。 |
| 设置与 API Key | 支持用户本地配置模型接口。 |

### 3.2 第一版暂不做

- 概念卡 / 对比卡
- PDF
- YouTube
- 移动端
- 账号系统
- 云同步
- 知识库式项目聚合
- 复杂成本预算
- 自动换模型重试

### 3.3 范围原则

第一版要优先保证一个完整学习闭环成立，而不是把功能做得很多。

## 4. 用户流程

### 4.1 首次使用

1. 用户安装扩展并打开任意技术网页。
2. 用户打开侧边栏。
3. 如果未配置 API Key，先进入设置页。
4. 用户配置 provider、base URL、API Key、model 和输出语言。
5. 回到网页后，选择整页生成或选中段落生成。

### 4.2 正常学习流程

1. 用户点击生成。
2. 系统先输出学习地图。
3. 用户看完学习地图后，点击“开始训练”。
4. 系统生成重点摘要和选择题自测。
5. 用户逐题作答，查看答案、解析和原文依据。
6. 学习包自动保存在本地历史中。
7. 用户可在历史页查看、删除或导出学习包。

### 4.3 体验原则

- 先定路径，再进入训练。
- 先看到学习地图，再看重点和题目。
- 每条关键结论尽量能回到原文。
- 用户始终能知道当前处于哪个阶段。

## 5. 功能需求

### 5.1 侧边栏入口与设置

- 产品以 Chrome / Edge 侧边栏形式呈现。
- 默认进入学习入口。
- 设置页需支持 provider、base URL、API Key、model、输出语言。
- 输出语言默认中文解释，并保留英文术语。
- 未配置 API Key 时，明确提示用户先完成设置。

### 5.2 内容提取

- 默认处理当前整页内容。
- 如果用户选中了段落，则支持按选中内容生成。
- 页面提取失败时，提示用户改为选中内容后再试。
- 提取内容至少应包含标题、URL、正文文本和用于定位的基础信息。

### 5.3 学习地图

- 学习地图是第一屏优先结果，本质上是“读前导读”。
- 它不是摘要，也不是题目，更不是让用户选择不同路线的菜单。
- 它要把当前网页拆成一个可理解的学习骨架，帮助用户先知道“这篇该怎么读”。
- 第一版学习地图至少包含：
  - 这篇资料在讲什么
  - 文章/章节的基本结构
  - 核心概念有哪些
  - 概念之间怎么串起来或依赖
  - 推荐阅读顺序是什么
  - 哪些地方容易混淆或出坑
  - 可能需要先补的前置知识
- 学习地图的作用是帮助用户在进入训练前先建立方向感，而不是把正文压缩掉。

### 5.4 开始训练

- 学习地图生成后，用户点击“开始训练”进入第二阶段。
- 训练阶段再生成重点摘要和选择题。
- 训练阶段的内容应围绕学习地图里的核心结构展开。

### 5.5 重点摘要

- 重点摘要用于提炼网页中的关键结论。
- 内容需中文解释，并保留英文术语。
- 每条重点尽量附带原文摘录和简单定位信息。

### 5.6 选择题自测

- 自测围绕网页核心内容生成。
- 题量规则沿用总计划：
  - 短文：3 题
  - 中等文章：5 题
  - 长文：8 题
- 每道题答完后立刻展示：
  - 正确答案
  - 答案解析
  - 原文依据

### 5.7 原文依据

- 所有重点和题目解析尽量保留原文摘录。
- 尽量支持回到原网页对应位置。
- 如果无法精确定位，也要保留可核对的摘录信息，而不是直接丢失依据。

### 5.8 本地保存与历史

- 学习包默认保存在浏览器本地。
- 以 URL 作为归档主键。
- 同一 URL 允许保留多个版本。
- 历史页按生成时间倒序展示，默认打开最新版本。
- 用户可以删除单个版本，而不是强制删除整条 URL 记录。

### 5.9 Markdown 导出

- 支持导出完整学习包为 Markdown。
- 导出内容至少应包含：
  - 标题
  - URL
  - 学习地图
  - 重点摘要
  - 选择题
  - 答案解析
  - 原文依据

## 6. 状态与异常处理

### 6.1 主要状态

- 未配置 API Key
- 正在提取内容
- 正在生成学习地图
- 等待用户点击“开始训练”
- 正在生成重点和自测
- 训练中
- 已保存
- 导出中
- 失败

### 6.2 异常处理

| 场景 | 处理方式 |
|---|---|
| 无 API Key | 提示用户先去设置页配置。 |
| 提取失败 | 提示用户选中网页内容后再试。 |
| AI 失败 | 保留已经生成的部分，并提示重试。 |
| AI 返回格式不合法 | 进入失败态，展示可读错误，并尽量保留已生成内容。 |
| 原文定位失败 | 保留原文摘录，定位能力降级而不是整包失败。 |
| 内容过长 | 优先保证学习地图先可用，必要时提示用户缩小范围或改用选中内容。 |

### 6.3 失败原则

- 已经生成的结果不能因为后续失败而完全丢失。
- 错误提示必须让用户知道下一步该怎么做。
- 失败时优先保住学习地图，其次保住重点和题目。

## 7. 数据与历史结构

### 7.1 学习包基础字段

每个学习包至少包含：

- 标题
- URL
- 生成时间
- 输入范围（整页 / 选中段落）
- 学习地图
- 重点摘要
- 选择题
- 答案解析
- 原文摘录
- 简单定位信息
- 导出状态

### 7.2 历史组织方式

- 历史按 URL 归档。
- 同一 URL 可保存多个版本。
- 历史列表按时间倒序排列。
- 默认查看最新版本。
- 删除以“单个版本”为最小粒度。

### 7.3 存储原则

- 第一版只做本地存储。
- 不做账号绑定。
- 不做云同步。
- 不做跨设备共享。

## 8. 验收标准

### 8.1 正常场景

- 打开一篇普通技术博客时，能够先生成学习地图，再进入训练，最终得到重点摘要和选择题自测。
- 打开一篇官方技术文档时，长内容仍能先返回学习地图，再继续生成训练内容。
- 选中段落时，系统能只处理选中内容。

### 8.2 历史与导出

- 同一 URL 多次生成后，历史页能看到多个版本。
- 默认打开最新版本。
- 可以删除某个单独版本。
- Markdown 导出内容完整，至少包含标题、URL、学习地图、重点、自测、解析和原文依据。

### 8.3 异常场景

- 无 API Key 时，用户能明确跳到设置页。
- 提取失败时，用户能通过选中内容继续生成。
- AI 返回异常时，已生成部分不丢失。
- 原文定位失败时，仍能看到可核对的摘录。

### 8.4 产品完成标准

如果用户能沿着“学习地图 -> 开始训练 -> 重点摘要 -> 自测 -> 原文回看 -> 本地保存/导出”完整走完一次流程，就说明第一版 PRD 目标成立。
