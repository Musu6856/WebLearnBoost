# 05 原型说明

## 1. 原型目的

这一版原型的目标不是做最终视觉稿，而是做一个足够接近真实产品的高保真 HTML 原型，用来验证 WebLearnBoost 第一版 MVP 的核心流程是否成立。

重点验证三件事：

- 用户打开网页后，能不能自然理解“先生成学习地图，再开始训练”。
- 学习地图、重点摘要、自测、原文依据放在浏览器侧边栏里是否清晰。
- 设置、历史、导出这些支撑功能会不会打断学习流程。

这次不再先做低保真线框图，直接用 Open Design 生成更完整的桌面端产品原型。

## 2. 原型形式判断

暂时不优先使用 Figma。

原因：

- 当前更需要快速验证产品流程，而不是花大量时间打磨静态画板。
- Open Design 可以直接生成可预览的 HTML 原型，比静态图更接近后续前端开发形态。
- WebLearnBoost 本身是浏览器插件侧边栏工具，用 HTML 原型更容易表达真实布局、状态和交互。

建议路径：

1. 用 `05_原型说明.md` 明确页面结构、关键状态和交互要求。
2. 在 Open Design 中选择偏高保真的原型能力，优先使用 `web-prototype`，不要使用 `blog-post`。
3. 设计系统可以先用 `Neutral Modern` 或当前的 `Claude` 风格，重点看流程，不纠结品牌视觉。
4. 生成第一版高保真原型后，先人工检查主流程是否清楚。
5. 原型确认后，再开始写产品代码。

需要注意：高保真原型不等于最终 UI。它的作用是帮助我们更早看到产品长什么样、流程是否顺，而不是一次定稿。

## 3. 原型范围

第一版原型只覆盖桌面浏览器插件形态。

产品以 Chrome / Edge 侧边栏形式出现，用户主浏览区仍然是当前网页，WebLearnBoost 显示在右侧侧边栏中。

原型需要展示：

- 网页上下文
- 插件侧边栏
- 学习地图生成流程
- 开始训练后的重点摘要与自测
- 原文依据回看入口
- 本地历史
- 设置页
- 关键异常状态

不展示：

- 落地页
- 手机端
- 账号系统
- 云同步
- PDF / YouTube
- 复杂品牌视觉系统

## 4. 原型画面结构

建议画面尺寸按桌面端浏览器窗口处理，例如 1440 x 900。

整体布局：

- 左侧约 60%：当前网页内容预览。
- 右侧约 40%：WebLearnBoost 插件侧边栏。
- 侧边栏宽度建议约 420px 到 520px。
- 整体看起来应像真实浏览器里打开了一个技术文档页面，同时右侧打开插件面板。

左侧网页预览需要包含：

- 技术文章标题
- 作者或来源信息
- 正文段落
- 小标题
- 代码块
- 术语高亮
- 被引用或定位的原文片段提示

右侧插件侧边栏需要包含：

- 产品名：WebLearnBoost
- 当前网页标题
- 当前 URL 简略信息
- 当前阶段状态
- 历史入口
- 设置入口
- 主流程内容区

## 5. 主要界面

### 5.1 学习入口

用户打开侧边栏后的默认界面。

需要包含：

- 当前网页标题
- 当前 URL 的简略显示
- 输入范围选择：整页 / 选中段落
- 主操作按钮：生成学习地图
- 辅助入口：历史、设置
- API Key 未配置时的提示

如果用户已经选中了网页中的一段文字，界面需要明确显示“将基于选中内容生成”。

### 5.2 生成中状态

学习地图生成过程中需要展示清晰状态。

建议拆成几个阶段提示：

- 正在提取网页内容
- 正在分析文章结构
- 正在生成学习地图

这里不需要复杂动画，但需要让用户知道系统没有卡死。

### 5.3 学习地图页

学习地图是第一阶段结果，不是摘要，也不是可选路线菜单。

页面需要展示：

- 这篇资料在讲什么
- 文章结构
- 核心概念
- 概念之间的关系
- 推荐阅读顺序
- 容易混淆或踩坑的地方
- 可能需要先补的前置知识

页面底部放主操作按钮：

- 开始训练

这里的“开始训练”意思是进入第二阶段，生成重点摘要和选择题自测，不是让用户选择某条学习方向。

### 5.4 训练页

用户点击“开始训练”后进入训练页。

训练页需要展示：

- 重点摘要
- 选择题自测
- 原文依据
- 保存状态
- 导出 Markdown

建议采用同一页纵向结构，而不是跳到完全不同页面：

1. 顶部保留当前阶段状态。
2. 先展示重点摘要。
3. 再展示选择题自测。
4. 每道题答完后展开答案、解析和原文依据。

### 5.5 自测答题状态

每道选择题需要展示：

- 题干
- 选项
- 提交答案按钮
- 用户选择后的反馈
- 正确答案
- 答案解析
- 原文摘录
- 回到原文按钮

第一版只做逐题反馈，不做复杂考试模式。

### 5.6 历史页

历史页用于查看已经生成过的学习包。

需要展示：

- 按 URL 分组的历史记录
- 同一 URL 下的多个版本
- 生成时间
- 输入范围：整页 / 选中段落
- 打开版本
- 删除单个版本
- 导出 Markdown

默认打开最新版本。

### 5.7 设置页

设置页需要支持本地模型配置。

需要展示：

- Provider
- Base URL
- API Key
- Model
- 输出语言
- 保存按钮
- 返回学习入口

API Key 不需要明文展示，可以用密码输入框。

## 6. 关键状态

原型里至少需要覆盖这些状态：

- 未配置 API Key
- 空状态：当前网页还没有生成学习包
- 正在提取内容
- 正在生成学习地图
- 等待用户点击开始训练
- 正在生成重点和自测
- 自测中
- 已保存
- 导出中
- 失败

失败状态至少包括：

- 页面提取失败
- AI 生成失败
- AI 返回格式不合法
- 原文定位失败

失败时需要体现一个原则：

已经生成的内容不应该因为后续失败而丢失。

## 7. 视觉与交互原则

视觉方向：

- 高保真、现代、克制、工具感强。
- 浅色界面为主。
- 可以用少量暖色或蓝绿色作为强调色。
- 圆角控制在 8px 左右。
- 使用细边框、轻阴影、清晰分组。
- 不要做营销页。
- 不要做卡通插画。
- 不要做低保真线框。
- 不要把界面做得太花。

交互原则：

- 用户始终知道当前处于哪个阶段。
- 学习地图必须先出现，训练内容不能和学习地图同时一股脑出现。
- 学习地图不做成“学习方向选择器”。
- 重点和题目尽量带原文摘录。
- 原文定位失败时，也要保留可核对的原文摘录。
- 设置和历史是支撑功能，不能抢主流程。
- 导出 Markdown 是结果动作，不是主流程入口。

## 9. 开始写代码前的判断标准

满足下面条件后，再进入产品代码开发：

- 侧边栏主流程已经在原型里跑通。
- 你能接受学习地图页的内容结构。
- 你能接受训练页里重点摘要、自测、原文依据的排列方式。
- 设置页和历史页不会明显干扰主流程。
- 异常状态有基本兜底方案。
- 高保真原型看起来像真实工具，而不是营销展示页。

如果这些还没确认，就先继续改原型，而不是急着写代码。
