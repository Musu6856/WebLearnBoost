# 06 开发说明

## 1. 文档用途

这份文档是 WebLearnBoost 进入代码开发前的交接说明，主要给后续在代码目录中新开的开发对话使用。

它不是 PRD，也不是原型说明，而是把前面的产品文档和 Open Design 最新原型收束成第一版可执行开发任务。

后续开发对话的目标不是重新讨论产品方向，而是在明确边界下初始化工程、实现浏览器插件、跑通第一版 MVP。

## 3. 第一版开发形态

第一轮开发直接做真实 Chrome / Edge 浏览器插件，不做网页 Demo。

开发目录：

```text
D:\Agent测试\WebLearnBoost_Project\WebLearnBoost
```

产品形态：

- Chrome / Edge 扩展。
- 右侧侧边栏 UI。
- 用户在任意技术网页中打开 WebLearnBoost。
- 插件读取当前网页内容，生成学习地图和训练内容。
- 设置、历史、导出均在插件侧边栏内完成。

第一版不做独立 Web App，不做营销页，不做移动端。

## 4. MVP 功能范围

第一版必须实现：

- 浏览器插件基础工程。
- 侧边栏 UI。
- 当前网页内容提取。
- 整页 / 选中段落两种输入范围。
- API Key 与模型配置。
- 学习地图生成。
- 点击“开始训练”后生成重点摘要和选择题自测。
- 自测逐题反馈、答案解析、原文依据。
- 原文摘录与简单定位。
- 本地历史保存。
- 同一 URL 多版本记录。
- 单个版本删除。
- Markdown 导出。

第一版暂不实现：

- PDF 导出。
- Notion 同步。
- 深色模式。
- 云同步。
- 账号系统。
- 移动端。
- PDF / YouTube 内容处理。
- 知识库式项目聚合。
- 自动换模型重试。
- 复杂成本预算。

Open Design 原型中如果出现 PDF、Notion、深色模式等内容，只作为视觉占位，不进入第一版开发范围。

## 5. 核心用户流程

### 5.1 首次使用流程

1. 用户安装扩展。
2. 用户打开任意 AI 技术文章或官方文档。
3. 用户打开 WebLearnBoost 侧边栏。
4. 如果未配置 API Key，侧边栏提示用户进入设置。
5. 用户填写 provider、base URL、API Key、model、输出语言。
6. 用户返回学习入口。

### 5.2 正常学习流程

1. 用户选择输入范围：整页 / 选中段落。
2. 用户点击“生成学习地图”。
3. 插件提取当前网页内容。
4. 系统先生成学习地图。
5. 用户阅读学习地图。
6. 用户点击“开始训练”。
7. 系统生成重点摘要和选择题自测。
8. 用户逐题作答。
9. 用户查看正确答案、解析和原文依据。
10. 学习包自动保存到本地历史。
11. 用户可导出 Markdown。

### 5.3 异常处理流程

- 无 API Key：提示用户先去设置页配置。
- 页面提取失败：提示用户改用选中段落后重试。
- AI 生成失败：保留已经生成的内容，并提供重试入口。
- AI 返回格式异常：展示可读错误，尽量保留已生成内容。
- 原文定位失败：保留原文摘录，不让整个学习包失败。
- 内容过长：优先保证学习地图先可用，必要时提示缩小范围。

### 5.4 历史与导出流程

1. 每次生成学习包后自动保存。
2. 历史按 URL 分组。
3. 同一 URL 可以保存多个版本。
4. 默认打开最新版本。
5. 用户可以删除单个版本。
6. 用户可以把当前学习包导出为 Markdown。

## 6. 界面与状态映射

### 6.1 学习入口

对应 Open Design 原型中的第一步。

需要展示：

- 当前网页标题。
- 当前网页 URL。
- 输入范围切换：整页 / 选中段落。
- API Key 状态提示。
- 主按钮：生成学习地图。
- 历史 / 设置入口。

### 6.2 生成中

点击生成后进入加载状态。

建议展示阶段提示：

- 正在提取网页内容。
- 正在分析文章结构。
- 正在生成学习地图。

这一步需要让用户明确知道系统正在处理，而不是卡死。

### 6.3 学习地图

学习地图是第一阶段结果，本质是读前导读。

需要展示：

- 这篇资料在讲什么。
- 文章结构。
- 核心概念。
- 概念关系。
- 推荐阅读顺序。
- 容易混淆点。
- 前置知识。
- 主按钮：开始训练。

学习地图不是摘要，也不是路线选择菜单。

### 6.4 训练页

用户点击“开始训练”后进入训练页。

需要展示：

- 重点摘要。
- 选择题自测。
- 当前题进度。
- 用户选项。
- 检查答案按钮。
- 答案解析。
- 原文依据。
- 定位到原文入口。
- Markdown 导出入口。

第一版只做逐题反馈，不做考试模式。

### 6.5 历史页

需要展示：

- URL 分组记录。
- 每条记录的标题、URL、生成时间。
- 多版本标识。
- 最新版本标识。
- 打开版本。
- 删除版本。

### 6.6 设置页

需要展示：

- Provider。
- Base URL。
- API Key。
- Model。
- 输出语言。
- 保存配置按钮。

API Key 使用密码输入框，不明文展示完整内容。

### 6.7 失败状态

失败状态必须给用户下一步动作。

示例：

- 页面提取失败：提示“请选中正文段落后重试”。
- AI 失败：提示“保留当前学习地图，可重试生成训练内容”。
- 定位失败：提示“无法自动定位，但已保留原文摘录”。

## 7. 数据与本地存储

### 7.1 设置项

设置项至少包含：

- `provider`
- `baseUrl`
- `apiKey`
- `model`
- `outputLanguage`

设置保存在浏览器本地。

### 7.2 学习包

学习包至少包含：

- `id`
- `title`
- `url`
- `createdAt`
- `inputScope`：`page` / `selection`
- `sourceText`
- `learningMap`
- `summary`
- `quiz`
- `answers`
- `explanations`
- `sourceQuotes`
- `locationHints`
- `exportStatus`

### 7.3 历史结构

历史按 URL 归档。

同一 URL 下允许多个版本，每次重新生成都创建一个新版本，不覆盖旧版本。

删除以单个版本为最小粒度。

## 8. AI 调用拆分

第一版建议拆成两次 AI 调用。

### 8.1 第一次调用：生成学习地图

输入：

- 页面标题。
- URL。
- 输入范围。
- 网页正文或选中段落。

输出：

- 这篇资料在讲什么。
- 文章结构。
- 核心概念。
- 概念关系。
- 推荐阅读顺序。
- 容易混淆点。
- 前置知识。

### 8.2 第二次调用：生成训练内容

触发条件：

- 用户已经看到学习地图。
- 用户点击“开始训练”。

输入：

- 页面标题。
- URL。
- 原文内容。
- 已生成的学习地图。

输出：

- 重点摘要。
- 选择题。
- 正确答案。
- 答案解析。
- 原文摘录。
- 简单定位信息。

### 8.3 返回格式要求

AI 返回内容必须结构化，便于渲染、保存和导出。

如果 AI 返回格式不合法，前端应进入可读失败态，并尽量保留已经生成的内容。

### 8.4 失败原则

- 学习地图生成失败：提示重试或改用选中段落。
- 训练内容生成失败：保留学习地图。
- 部分题目异常：保留可用题目，提示部分生成失败。
- 原文定位失败：保留原文摘录，不阻塞学习包保存。

## 9. 开发验收标准

第一版开发完成时，至少要通过以下场景：

- 普通技术博客：能提取整页内容并生成学习地图。
- 官方技术文档：长内容仍能先生成学习地图。
- 选中段落：只处理选中内容。
- 未配置 API Key：能明确进入设置页。
- 学习地图生成后：训练页才可进入。
- 训练页：能完成选择题作答、查看答案解析和原文依据。
- 原文定位失败：仍能看到可核对摘录。
- AI 失败：已生成内容不被清空。
- 同一 URL 多次生成：历史中出现多个版本。
- 删除历史：可以删除单个版本。
- Markdown 导出：包含标题、URL、学习地图、重点摘要、自测题、答案解析、原文依据。
